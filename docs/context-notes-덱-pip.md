# 덱 PiP — 결정과 이유

K 요청: "스트림덱은 버튼을 눌러서 pip로 나와야 해"

## 왜
방송 중엔 tikke 본 창이 TTLS 뒤에 있다. 덱을 쓰려면 창을 앞으로 꺼내야 하는데
그러면 방송 화면을 가린다. → 덱만 **항상 위에 뜨는 작은 창**으로 뽑는다.

## 창 설정
- `frame: false` — 제목표시줄 없이 버튼만
- `alwaysOnTop(true, "screen-saver")` — 전체화면 TTLS 위에도 뜬다
- `skipTaskbar: true` — 작업표시줄을 어지럽히지 않게
- 제목줄에 `WebkitAppRegion: "drag"` — 프레임이 없으면 이게 없인 창을 못 옮긴다
- 라우팅은 기존 팝업들과 같은 hash 방식 (`?deckpip=1#deck-pip`) — 본 renderer 재사용

## 함정 (이번 작업의 핵심)
PiP는 **별도 renderer**라 zustand 스토어를 자기 사본으로 따로 갖는다.
거기서 액션을 직접 실행하면 PiP 안의 사본만 바뀌고 본 창은 그대로다 (TTS가 안 꺼짐).

→ 모든 버튼은 `tikke.deck.press(id)` 로 main 을 거쳐 본 창으로 보낸다.
본 창의 Deck 페이지도 **같은 경로**를 쓴다. 경로를 둘로 두면 언젠가 갈린다.

같은 이유로 App 의 카탈로그 등록 useEffect 는 PiP/채팅/게임 팝업 renderer 에서 건너뛴다.
본 창만 등록한다. 안 그러면 팝업이 뜰 때마다 카탈로그를 덮어쓴다.

## 부가
액션에 `deck:pip`("덱 창 열기")를 넣었다. 스트림덱 버튼 하나로 덱 창 자체를 띄울 수 있고,
동시에 PiP 경로를 HTTP로 실측할 수 있는 통로가 된다.

## PiP 안에서 편집 (K 요청: "저 pip 창 안에서도 기능들을 추가할 수 있어야돼")
헤더에 `✏️ 편집` 토글. 켜면 각 버튼에 빼기(×), 끝에 `+`. `+` 를 누르면 액션 목록이
헤더 아래로 펼쳐지고 고르면 들어간다.

배치는 본 화면(Deck 페이지)과 **같은 40칸 배열**을 공유한다.
PiP 는 채워진 칸만 보여주되 **원래 칸 번호를 기억**하고, 추가는 첫 빈 칸에 넣는다.
이렇게 안 하면 PiP 에서 편집할 때마다 본 화면 5×8 격자가 앞으로 밀려 흐트러진다.

알려진 한계: 본 화면과 PiP 를 동시에 열어두고 양쪽에서 편집하면 나중에 저장한 쪽이 이긴다.
(양방향 실시간 동기화는 안 넣음 — 필요해지면 그때)
