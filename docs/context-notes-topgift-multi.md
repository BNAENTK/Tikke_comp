# 멀티 탑기프트 — 2·3등에 엉뚱한 선물이 뜨던 것 (2026-08-11)

증상(K 제보 + 스샷): 1등은 고래 다이빙으로 맞는데 2·3등이 1다이아 선물로 나온다.
"1등 제외한 2, 3등 선물이 무시되고 있다."

## 원인 — 유실이 아니라 집계 단위

선물 이벤트는 정상 도착했다. `event_logs` 400건 실측: `diamondCount` 0/누락 **0건**,
구미호 1800, 고래 다이빙 2150 모두 값과 사진이 온전했다.

진짜 이유는 **고래 다이빙과 구미호를 같은 사람(서형지)이 보냈다**는 것이다.
`getMultiGiftTop` 이 사람 기준(사람당 한 줄, 그 사람의 최고 선물)이라 서형지는 2150 한 줄만
차지하고, 그의 구미호(1800)는 목록에서 밀려났다. 2·3등은 다른 사람들의 최고 선물이 1다이아라
그대로 올라온 것이다. 저장 상태 실측이 화면과 정확히 일치했다.

| 최고선물 | 다이아 | 사람 |
|---|---|---|
| 고래 다이빙 | 2,150 | 서형지 |
| 장미 | 1 | 찌누~ |
| 사랑해 주세요 | 1 | 헤헤 |

## 수정 — 선물 기준으로 (K 확인)

`getMultiGiftTop` 을 사람이 아니라 **선물**로 줄 세운다. 같은 사람이 여러 줄을 차지할 수 있다.
같은 선물을 여러 번 보낸 건 한 줄로 묶어 ×N.

그러려면 선물별 다이아가 필요한데 `giftFreq` 엔 개수·이름·사진만 있었다 → `coins` 추가.

**구버전 저장 데이터**엔 `coins` 가 없다. 최고가 선물은 `maxSingleCoins` 로 값을 알지만
나머지는 모른다 → 그런 줄은 **넣지 않는다**(틀린 숫자를 띄우느니 빠지는 게 낫다).
그 선물이 한 번 더 오면 그때부터 정확해지고, 집계는 하루마다 리셋된다.
즉시 정상화하려면 탑기프트 리셋 버튼.

단일 1등 표시(`recomputeTop`/`getCurrentTop`)는 건드리지 않았다 — 기존 오버레이 그대로.

## 검증

실제 `top-donor-service.ts` 를 번들해(electron 의존은 스텁) **실제 선물 이벤트 30건을 그대로 흘림**
(`scratchpad/topgift-test.mjs`).

```
1위  2150  고래 다이빙   서형지 ×1
2위  1800  구미호       서형지 ×2   ← 두 번 보낸 것이 한 줄로 묶임
3위  1000  블루밍 리본   서형지 ×1
4위     1  장미        서형지 ×5
5위     1  Rose      소금빵 ×3
```

K 가 고른 기대 출력과 일치.

구버전 데이터 회귀(`scratchpad/legacy-test.mjs`): 안 깨지고 값 아는 줄만 나온다(지금 화면과 동일).
단일 1등도 `2150 고래 다이빙 서형지` 그대로.

오버레이 쪽은 갱신할 때마다 목록을 새로 그리고 사람 id 로 키를 잡지 않아,
같은 사람이 여러 줄이어도 문제없다(확인함).

## 남은 것

`pnpm check:overlays` 가 `top-gift-ani.html` 의 desktop↔worker 불일치를 잡는데,
**다른 세션이 그 파일을 수정 중**(working tree, 커밋 전)이라 손대지 않았다. HEAD 기준으론 동일하다.
그 세션이 양쪽을 맞추면 해소된다.

# 애니메이션(anim) 탭 세로 나열 — "순환으로 적용된다" 제보 추적 (2026-08-12)

## 순환은 재현되지 않았다 — 전달 경로는 전부 정상

K 제보: anim 탭에서 "세로 나열"을 골라도 순환이 적용된다. 전 구간 실측:

| 지점 | 실측값 |
|---|---|
| DB `app_settings["topDonor:anim:settings"]` | `multiGiftLayout: "column"` |
| `tikke:topDonor:setSettings` (ipc.ts) | 설정 객체 통째로 local+cloud 브로드캐스트, anim→`top-gift` |
| 실행 중인 앱의 WS(18182) 캡처 | `SETTINGS top-gift => layout:"column"` |
| 앱이 서빙하는 HTML(18181) | `renderMultiLayout` 존재 |
| 라이브 `api.tikke.kr/overlay/top-gift-ani` | `renderMultiLayout` 존재 |

오버레이 `multiLayout()`도 `column`이면 `renderMultiLayout` 로 빠진다. 순환을 강제하는 지점은 없었다.
Playwright 로 같은 설정을 그대로 넣으면 세로 3장이 나온다.

**주의**: 설치본은 1.8.302 인데 세로 배치는 **v1.8.312 부터**다. 설치 앱으로 보면 실제로 순환한다.
지금은 dev 앱(electron, 소스 폴더)이 떠 있어 최신이지만, 재발 제보 시 **어느 쪽에서 봤는지(앱 미리보기 / TTLS)와
앱 버전**을 먼저 확인할 것. 두 경로는 배달 방식이 다르다.

## 대신 찾은 실제 결함 2건 (K 재설명: "켜기 전 디자인 그대로 + 세로 두 개만 추가")

1. **미리보기가 anim 탭에서 짜부라졌다** — `TopDonor.tsx` 의 `multiPreview` 가 `tab === "a"` 만이라
   anim 탭 멀티에는 높이 420·배율 예외가 안 걸렸다. 220px 안에 세로 3장 → 자동맞춤이 극단 축소.
   세로로 고른 티가 안 나서 "적용이 안 된다"로 보이기 충분했다. → `(tab === "a" || tab === "anim")`.
2. **1위 카드가 원본과 달랐다** — `.mg-clone .top-gift-title { display:none }` 이 모든 클론의
   "TOP GIFT" 타이틀을 지웠다. K 요구는 1위 = 켜기 전 카드 그대로다. → `:not(:first-child)` 로 좁혀
   1위만 타이틀 유지(왕관 1위 규칙과 같은 결).

## 세로 간격은 70px 그대로 두라

18px 로 줄여봤다가 카드끼리 겹쳤다. 선물 이미지가 `giftYOffset` 으로 카드 밖까지 나와
**자연 높이가 시각 높이보다 작기** 때문이다. 축소가 심한 건 간격이 아니라 미리보기 높이 문제였고,
그건 위 1번으로 해결된다. 실측: 70px 일 때 카드 사이 34px 여백, 겹침 없음.

1위 카드에서 타이틀이 선물 이미지에 살짝 가리는 건 K 의 `giftYOffset: -18` 설정 그대로다 —
멀티 끈 원본도 똑같이 가린다. 버그 아님.

## 클론이 원본 카드 스타일을 통째로 놓치고 있었다 (폰트 통일 — K 요청)

K: "일반 설정 폰트와 멀티 폰트를 통일시켜". 실측하니 원본 `.top-gift-name` 은
`Black Han Sans` 인데 클론은 `Malgun Gothic`(브라우저 기본)이었다.

원인은 폰트만의 문제가 아니다. 카드 스타일이 **`#topGiftInner` (id 셀렉터)** 에 걸려 있는데
`renderMultiLayout` 이 클론에서 id 를 지우므로(중복 id 방지) **그 규칙 전체가 안 걸린다**.
그래서 `font-family` 뿐 아니라 `display:flex`·`flex-direction:column`·정렬·`gap:6px` 까지 같이
빠져 있었다(자식이 block 이라 세로로 보이긴 해서 눈에 안 띄었다).

→ `#mgCards > .mg-clone` 에 그 속성들을 그대로 준다. **`transform` 은 빼야 한다** —
스케일은 컨테이너(`#mgCards`)가 담당하므로 클론에도 주면 이중으로 적용된다.

검증: 원본과 클론 3장 모두 `"Black Han Sans", "Noto Sans KR", sans-serif` 동일,
`display:flex` 확인. 세로 활성 중에 `titleText` 를 바꿔도 1위 카드에 즉시 반영된다
(원본 템플릿이 문서상 먼저라 `document.querySelector('.top-gift-title')` 가 클론을 잡지 않는다 — 확인함).
