# 리그 랭킹 페이지 — 결정 사항

## 왜 만드나
빈 리그의 부트스트랩 호스트를 찾으려면 "그 리그에 누가 있는지, 아이디가 뭔지"를 봐야 한다.
지금은 내가 SQL로 뒤져서 K에게 물어보는 방식인데, 앱에서 바로 보이면 그 왕복이 사라진다.

## 외부 대조 사이트 방식을 따른 이유 (K 지시)
외부 대조 사이트 `/ranking/a1` DOM을 직접 확인했다.
- 목록: 순위·닉네임·점수·조각 수. **`LIVE` 문자열 0건, `@아이디` 0건**
- 행 클릭 → 팝업에 프로필 사진·닉네임·`@아이디`·LIVE 배지·버튼 3개

즉 라이브 판정을 목록 전체에 하지 않는다. 우리도 같은 구조를 따르면
서명 API 쿼터를 태우지 않으면서 필요한 순간에만 정확한 값을 얻는다.

## 데이터 출처
`broadcaster_rank_snapshots` (Supabase, anon 읽기).
`region='kr'` 필터는 필수 — 이 컬럼이 없던 시절 해외 순위표가 한국 리그로 저장돼
A1 1위가 Tyler River 2,197,445로 찍힌 사고가 있었다(상세: context-notes-league-harvester.md).

## 라이브 확인
`room-observer.fetchRoomSnapshot(uniqueId)` 재사용. 이미 `isLive`·`roomId`를 돌려주고
`net.fetch` 스크래핑이 아닌 정식 경로다. 클릭한 한 명만 조회한다.

## 구현 중 확인한 것

**페이지는 이미 있었다.** `LeagueRankings.tsx` + 사이드바 `leagueranking`이 이미 연결돼 있었고
리그 선택·100행·조각 구간까지 나왔다. 없던 건 상세 팝업뿐이라 그것만 추가했다.

**`fetchRoomSnapshot`은 실패해도 null을 안 준다.** 네트워크/서명 실패 시 `isLive:false`인
offline 객체를 돌려준다. 그대로 쓰면 방송 중인 사람이 조회만 실패해도
"현재 방송 중이 아닙니다"로 단정 표시된다. 반환분에만 `fetchFailed`를 붙여 구분했다 —
`snapshots` 맵에 담기는 값은 건드리지 않아 폴링(room-observer/harvester) 동작은 그대로다.

**아바타는 이니셜 위에 이미지를 덮는다.** TikTok CDN 아바타 403 전례가 있어
`onError`로 이미지만 지우면 이니셜이 남는다. [[feedback_no_app_freeze]] 계열의 같은 처방.

**이니셜은 `[...str][0]`.** `slice(0,1)`은 닉네임 첫 글자가 이모지일 때 서로게이트 페어를
쪼개 `�`가 나온다. 한국 리그 닉네임은 대부분 이모지로 시작해 거의 항상 터진다.

# 2차 — 표시층 재제작 (2026-08-04)

## 복소라이브(voxo.live)에는 리버스할 리그 시스템이 없다

랜딩에 두 번 명시돼 있다 — "제3자(tik.tools) 집계 참고용 · 틱톡 공식 아님".
tik.tools 는 TikTok LIVE API 상용 벤더로, 28개 지역 리더보드와 A1~D5 리그 클래스를
`Ultra+` 유료 등급으로 판다. voxo 는 그걸 사서 렌더링만 한다.

즉 "voxo 를 분석해서 가져온다"가 성립하지 않는다. 남는 건 **살까 만들까** 뿐인데,
2026-08-03 실측에서 tikke 자체 수집이 외부 대조 사이트와 96~99% 일치했다(A3·B1·B3·C1·C3).
tikke 는 TTLS `rank_type=16` 원본을 직접 읽고 tik.tools 는 자기 입으로 "estimates" 라고 쓴다.
벤더로 갈아타는 건 품질 하락 + 외부 의존이라 하지 않는다.

확인한 voxo 공개 엔드포인트(무인증) 2개.
- `GET /api/public/ranking/global-teaser` — 지역별 top3 + liveCount.
  **4~7위는 클라이언트가 지어낸다** (`'creator'+i+'****'`, 점수는 `top[2].score*(1-i*0.08)`).
  실데이터는 top3 뿐이다.
- `GET /api/public/ranking/check/<uniqueId>` — `{ok, enabled, found, classLabel}`.
  가입 없이 리그만 알려주고 정확한 순위는 가려서 로그인을 유도한다.

voxo 서버 내부는 확인하지 않았다(공개 엔드포인트 2개만 봤다). 벤더 중계라는 건 추정이다.

## 그래서 외부 대조 사이트를 기준으로 삼았다

외부 대조 사이트는 순위 페이지가 전부 공개라 마크업과 스크린샷을 실측할 수 있고,
2026-08-03 대조에서 외부 대조 사이트와 voxo 는 서로 정확히 일치했다. 볼 수 있는 쪽을 기준으로 쓴다.

외부 대조 사이트 레이아웃 4요소.
1. 헤더 — 제목 + 리그 배지, 우측 리그 드롭다운 / 히스토리 / 새로고침
2. 조각 득실 구간 카드 — 밴드마다 `배지(-1·0·+1·+2·+3)` + `퍼센트` + `축약값` + `(정확값)`
3. 구간 색상 범례
4. 순위 행 — `메달+순위` / `아바타` / `닉네임 + 조각:N` / `점수 + 조각+N`

**1차 때 적어 둔 "외부 대조 사이트 목록엔 LIVE 표시 0건"은 지금은 틀리다.** 오늘 실측하니 아바타에
분홍 링 + 우하단 점으로 라이브를 표시하고 alt 에도 "(라이브 중)" 이 들어간다. 그 사이 바뀌었다.

## 데이터 격차 — 실측하고 결정한 것

`broadcaster_rank_snapshots` 컬럼을 직접 확인했다. **아바타 URL 도 라이브 플래그도 없다.**
`saveLeagueRanks` 는 `ranks[]` 에서 id/display_id/nickname/rank/score/room_id 만 꺼낸다.

- **아바타**: 저장하지 않는다. TikTok CDN 아바타 URL 은 서명 + 만료(`x-expires`)라
  한 번 받아 두고 끝이 아니라 갱신 주기가 따라온다. 수집 변경 + 컬럼 추가가 필요한데
  이번 지시는 표시층 교체였다. **이니셜 원형 플레이스홀더**로 자리를 잡아 두고
  응답 타입에 `avatar?: string` 을 열어 뒀다 — 나중에 컬럼이 생기면 채우기만 하면 된다.
- **라이브 여부**: `room_id` 로 대신할 수 있을 줄 알았는데 오늘치 1,531행 **전부**가 room_id 를 갖고 있다.
  라이브 구분자가 아니다. 그래서 목록에는 라이브 표시를 넣지 않았다.
  (데스크탑은 행을 눌렀을 때만 `rooms.check` 로 1회 조회 — 1차 결정 그대로.)
- **보유 조각(`조각: N`)**: `user_league_data.owned_fragments` 에 있다.
  오늘치 스냅샷 1,531행이 `display_id` 로 **100% 조인된다**. 다만 `owned_fragments` 가 채워진 건
  그중 54행(3.5%)뿐이라, 값이 있을 때만 보여주고 없으면 숨긴다.

  외부 대조 사이트는 100명 전원에 이 값이 있다. `ranks[]` 행 자체에 조각 정보가 실려 있고 우리가 안 꺼내는 것으로
  보이지만 **rank_view 덤프가 없어 필드명을 확인하지 못했다. 추정이라 코드로 옮기지 않았다.**
  확인하려면 살아 있는 앵커로 `fetchClassRankRaw` 를 한 번 떠서 `ranks[0]` 을 통째로 덤프해야 한다.

## 조각 두 종류를 섞지 말 것

- `조각+N` = 순위표 점수를 그 리그 캐논 퍼센타일 컷과 비교한 **이번 라운드 획득분**
- `조각: N` = TikTok 이 주는 **누적 보유량**. 점수로 계산할 수 없다

둘은 다른 값이고 외부 대조 사이트도 따로 보여준다 — A1 6위는 `조각:3` 인데 `조각+2` 다.

## 서브 변경

`rankings.ts` 에 `fetchOwnedFragments()` 를 더했다. `user_league_data` 를 훑어
`display_id → owned_fragments` 맵을 만들고 행에 `owned` 로 붙인다.
이 조회가 실패해도 순위표는 나가야 하므로 try/catch 로 감싸 빈 맵을 돌려준다.
응답 구조가 바뀌었으니 `CACHE_KEY` 를 v5 로 올렸다 — 안 올리면 배포 후에도
`:stale`(24시간)에 남은 옛 응답이 계속 나간다.

## 웹 페이지가 서빙되지 않고 있다 (K 판단 필요)

`apps/web/src/pages/LeagueRankings.tsx` 는 **어디에도 마운트돼 있지 않다.**
- `src/main.tsx` 를 참조하는 HTML 이 하나도 없다(`grep main.tsx` 0건)
- 루트 `index.html` 에 `<div id="root">` 가 없다
- `https://tikke.kr/ranking` 은 200 이지만 내용은 랜딩 페이지다(Pages SPA 폴백)
- 빌드가 4모듈만 변환한다 — `App.tsx` 가 번들에 안 들어간다

즉 React 쪽 웹 페이지는 죽은 코드다. 실제로 서빙되는 리그 페이지는 `cutoffs/index.html`(순수 HTML)뿐이다.
이번에 웹 파일도 같이 고쳤지만 **연결하지 않으면 사용자에게 안 보인다.** 두 갈래가 있다.
1. `ranking/index.html` 을 `cutoffs/index.html` 처럼 순수 HTML 로 새로 쓴다(현행 배포 방식과 일치)
2. React 앱을 살려 엔트리를 붙인다(빌드·배포 경로 손봐야 함)

어느 쪽이든 이번 지시 범위 밖이라 손대지 않았다.

## 조각 표시 커버리지

로컬 워커(v5) 실측: 851행 중 `owned` 가 있는 행 **15개(1.8%)**. A/B 리그 상위권은 거의 없다.
없는 행은 조각 줄을 비우되 `minHeight` 로 자리를 잡아 행 높이가 들쭉날쭉해지지 않게 했다.
커버리지를 올리려면 `ranks[]` 행에서 조각 정보를 꺼내야 하는데 필드명 미확인 상태다(위 참고).

## 보류 리그 구분

`pickLeagueRows` 가 일관성 검사로 버린 리그(A1·C4)는 rows 가 비는데, 이게 "데이터 없음" 과
똑같이 보이면 고장으로 읽힌다. 응답에 `suppressed` 를 실어 화면 문구를 나눴다.
기본 탭도 A1 고정에서 **첫 로드 시 비어 있지 않은 첫 리그**로 옮기게 했다 — A1 은 보류되는 일이 잦아
처음 열자마자 빈 화면이 나왔다(실측: A3 로 자동 이동).

## 숫자 표기를 K/M 으로 바꾼 이유

기존 순위 페이지만 만/억을 썼고, 실제 서빙되는 `cutoffs/index.html` 은 이미 `K`/`M` 이다.
외부 대조 사이트도 K/M 이다. 순위 페이지를 맞추는 쪽이 정합이다.

## 배포

K가 "배포는 하면 안 되고 일단 만들어야돼" 라고 명시했다. 커밋·버전업·태그·push 전부 하지 않았다.

## 남은 사항
- 이 페이지는 사이드바에서 `locked: true`다. `useHasLockAccess()`가 admin/vip만 통과시키므로
  일반 등급은 메뉴를 눌러도 안 열린다. 기존 설정이라 건드리지 않았다 — 공개하려면 K 판단 필요.
- 목록의 조각 라벨은 라운드 초반에 전원 최대 조각으로 보인다. 그 시각 컷 자체가 낮게
  관측돼서다(이 작업과 무관, 기존 동작). 낮 시간대에는 정상.
