# WEFLAB 분석 + Tikke 웹앱화 검토 (2026-08-13)

조사 방법: 공개 자산만(홈 HTML, `sitemap.xml`, `robots.txt`, 프론트 번들 `main.js` 653KB).
`/dashboard` 는 로그인 뒤라 직접 못 봄 — **로그인 시도하지 않았다.**

## 1. WEFLAB 은 무엇인가

한국 스트리머용 **웹 기반 올인원 오버레이 서비스**. 무료 + 일부 유료(시그니처 플러스).

- 지원 플랫폼: **SOOP(아프리카), 치지직, 유튜브, 트위치, 씨미(CIME)**
- 등록 채널 **154,610**, 표시 시점 동시 LIVE **4,227**
- 슬로건 그대로: *"별도 회원가입 없이 **아이디 입력만으로** 여러 플랫폼을 쉽게 연동"*

```
nginx/1.18 (Ubuntu)  +  PHP  +  jQuery  +  socket.io
자산: /resource/dist/main.js, vendor.js  (번들러 있음, 버전 쿼리로 캐시 무효화)
```

## 2. Tikke 를 웹앱으로 — 진짜 쟁점 하나

기능 목록이 아니라 **"누가 방송에 붙느냐"** 가 전부다.

```
지금 (데스크탑)          웹앱으로 가면
─────────────────       ──────────────────
사용자 PC 가 틱톡에 붙음   서버가 사용자 대신 붙어야 함
연결 비용 = 사용자 부담     연결 비용 = 우리 부담 (방송 수만큼)
서명 쿼터 = IP 분산        서명 쿼터 = 우리 IP 에 집중
```

Tikke 는 이미 **절반은 웹이다** — Cloudflare Worker + 클라우드 오버레이(`OverlayRoom` DO)로
오버레이는 이미 브라우저에서 돈다. 남은 건 **이벤트 수집을 어디서 하느냐**뿐이다.

### 걸림돌 A — 틱톡 서명(EulerStream)

지금도 익명 쿼터로 429 를 맞는다(메모리에 기록됨). 서버가 1,000 방송을 대신 붙으면
**서명 요청이 우리 계정 하나에 전부 몰린다.** 유료 서명 플랜 비용이 사업 모델을 좌우한다.
WEFLAB 이 지원하는 SOOP/치지직/트위치/유튜브에는 이 문제가 **없다** — 그래서 무료가 가능하다.

### 걸림돌 B — Cloudflare Workers 로는 못 한다

`tiktok-live-connector` 는 Node 라이브러리다. Workers 런타임에서 그대로 안 돈다.
**상시 켜진 Node 서버(VPS/Fly/Railway)가 따로 필요**하고, 방송 수만큼 WS 연결을 유지해야 한다.
지금 무료 티어 중심 구조에서 **처음으로 고정비가 생기는 지점**이다.

### 걸림돌 C — 로컬이라서 되던 것들

| 기능 | 웹앱에서 |
|---|---|
| TTS 로컬 합성(tikketonic ONNX) | ❌ 서버 GPU 필요하거나 클라우드 TTS 로 |
| 사운드 재생(로컬 스피커) | △ 브라우저 탭이 재생 — 탭을 켜둬야 함 |
| dB 미터 / 음성 명령(마이크) | △ 브라우저 권한으로 가능, 탭 필요 |
| 유튜브 음원 추출 / 신청곡 플레이어 | △ 탭에서 가능(지금도 별창) |
| GTA5 · 마인크래프트 연동 | ❌ 로컬 프로세스 통신 — 웹에서 불가 |
| 파일 저장(사운드 라이브러리) | △ 클라우드 저장으로 이전 필요 |

### 얻는 것

- **설치가 사라진다.** WEFLAB 이 15만 채널을 모은 진짜 이유다. "아이디만 입력"
- 업데이트가 즉시(지금은 릴리즈 빌드 → 자동 업데이트 대기)
- 모바일에서 대시보드 확인
- Mac/Linux 자동 지원

## 3. 갈 수 있는 세 갈래

### ① 완전 웹앱 (WEFLAB 방식)
서버가 붙고 브라우저는 대시보드+오버레이만.
- 장점: 설치 0, 유입 최대
- 단점: 고정비 발생, 서명 쿼터 집중, 로컬 기능 상실
- **틱톡 서명 비용이 답을 정한다.** 그것부터 계산해야 함

### ② 하이브리드 — 데스크탑을 "연결기"로, 웹을 "조작판"으로
데스크탑 앱은 계속 방송에 붙고, 설정·오버레이·모니터링은 웹에서.
- 지금 구조에서 **가장 적게 바꾸고 가장 많이 얻는다**(클라우드 오버레이가 이미 그 절반)
- 설치는 여전히 필요하지만, 모바일 조작·즉시 업데이트를 얻음
- 이미 있는 `apps/web` + 모바일 컴패니언(N21) 계획의 연장선

### ③ 웹앱은 유튜브 전용으로
유튜브는 서명이 없다. **웹앱은 유튜브(+치지직/트위치)로 시작**하고 틱톡은 데스크탑 유지.
- 앞서 조사한 유튜브 어댑터(`YouTube.js`)와 정확히 맞물린다
- 플랫폼별 강점을 그대로 쓴다: 틱톡=데스크탑, 나머지=웹
- WEFLAB 과 정면으로 겹치지만, **틱톡이라는 그쪽에 없는 무기**를 이미 갖고 있다

## ⚠ 앞 문서의 추정 하나가 틀렸다 — 유튜브는 **공식 API** 다

푸터에 **"YouTube Terms of Service" + "YouTube API Services Terms of Service"** 가 걸려 있고,
OAuth scope 가 `userinfo.email` + `userinfo.profile` + **`youtube.readonly`** 였다.
InnerTube 스크레이프가 아니라 **YouTube Data API 정식 사용**이다.

이게 중요한 이유: 쿼터는 **API 프로젝트(클라이언트 ID) 단위**라 사용자가 자기 토큰을 줘도
**분산되지 않는다.** 15만 채널을 공식 API 로 돌리려면 둘 중 하나다.
- Google 쿼터 증액 승인을 받았거나
- `liveChatMessages.streamList` 로 폴링 비용을 줄였거나

업데이트 기록의 두 줄이 후자를 시사한다:
- `[12월 10일] 유튜브 채팅이 **실시간 채팅(모든 메시지 표시)** 방식으로 변경`
- `[02월 26일] 유튜브의 여러 라이브(가로·세로 방송)를 **통합** 연동`

→ **우리도 유튜브는 공식 API 로 갈 수 있다는 실증.** 앞 문서에서 "쿼터 때문에 비공식" 이라고
기울었던 판단을 여기서 되돌린다. 다만 **streamList 단가 확인은 여전히 필요**하다.

## 연결 모델

채널 연결/해제 5종: **SOOP · 치지직 · 유튜브(Tikke 연결됨) · 트위치 · 씨미**. 각각 OAuth.

대시보드 안내 문구가 서버 연결 구조를 그대로 드러낸다:

> "테스트를 제외한 기능들은 **생방송을 시작해야 연결 가능**하며,
> 생방송 시작 직후 1분이 지나도 연결이 불가할 경우 **채팅 재연결**을 눌러주세요."

= 서버가 방송을 잡아 붙고, 실패하면 사용자가 수동 재시도. Tikke 데스크탑의 live-monitor 와 같은 문제를
같은 방식으로 다룬다.

## 수익 구조 — 참고할 만한 부분

본체는 무료. 대신 **별도 유료 서비스로 뺐다**:
- **큰손매니저** — "내 방송의 큰손을 탐지·분석", 활동 카테고리 분석, 큰손 전용 시그니처. 7일 무료 체험.
- 시그니처 플러스 — 저장 용량

즉 **오버레이는 무료로 뿌려 사용자를 모으고, VIP 분석을 판다.**
Tikke 의 단골 카드/CRM·탑기프트가 정확히 그 자리에 있다. 로드맵(세션리포트·단골케어·충성도포인트)과 겹친다.

기타: 계정 공유(매니저 위임), 알리미(스트리머 홍보 게시판 — 커뮤니티 유입 장치), 채팅 번역.

## 다시 정리한 권고

앞 문서의 ③안(**웹앱 = 유튜브·비틱톡, 데스크탑 = 틱톡**)이 더 유력해졌다.
유튜브를 공식 API 로 갈 수 있으면 ToS 회색지대를 피하면서 웹앱이 성립한다.
확인할 것은 이제 하나로 좁혀진다 — **`streamList` 쿼터 단가와 증액 승인 난이도.**
