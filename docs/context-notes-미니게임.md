# 컨텍스트 노트 — 미니게임 (합10 사과 / 컬러 매치)

작성 2026-07-30. 결정과 그 이유를 계속 덧붙인다.

## 원본 규칙 (2026-07-30 확인)

참고 사이트 `apple.oshizi.com` / `color-tiles.oshizi.com` 의 게임 방법 문서에서 확인함.

**사과게임** — 10×17 보드, 각 칸 1~9. 직사각형 영역을 드래그해 그 안의 숫자 합이
정확히 10이면 사과가 제거된다. 2분. 많이 제거한 사람이 승리. 멀티는 6글자 방코드,
같은 방의 모든 플레이어가 **같은 시드의 보드**를 각자 플레이하고 호스트가 시작을 누른다.

**컬러타일** — 보드에 200개 타일. **빈 칸**을 클릭하면 그 칸 기준 상/하/좌/우 4방향으로
각 방향 첫 타일(또는 가장자리)까지 스캔한다. 4방향 중 **2방향 이상에서 같은 색**이
발견되면 그 타일들이 사라진다. 타일 1개당 1점. 매치 실패 클릭은 미스이고 **남은 시간 -10초**.
120초, 200개를 먼저 다 지우면 즉시 승리.

## 저작권 판단

게임 규칙 자체는 저작권 보호 대상이 아니다. 원조는 GameSaien의 Fruit Box이고
oshizi도 멀티를 붙인 후발 구현이다. 규칙만 보고 직접 구현하며 **저쪽 코드·이미지·이름은
쓰지 않는다.** 이름은 `합10 사과` / `컬러 매치`로 간다.

## 참여 방식 (K 결정)

세 경로를 모두 지원한다.

1. **방송 코옵** — 방송인 보드 하나를 시청자가 채팅 좌표로 함께 지운다. 개인별 점수 랭킹.
   시청자는 설치·접속이 전혀 필요 없다. 기존 초성퀴즈와 같은 역학(먼저 맞힌 사람 득점).
2. **룸 대전** — tikke 앱 사용자끼리 6글자 방코드로 모여 같은 시드 보드를 각자 레이스한다.
3. **혼자** — 앱 안에서 단독 연습.

### 왜 채팅 좌표인가

TikTok LIVE에서 시청자로부터 오는 입력은 **채팅과 선물뿐**이다. 드래그·클릭은 불가능하다.
따라서 원본의 마우스 조작을 그대로 옮길 수 없고 좌표 입력으로 치환한다.

```
!사과 B3 D5     좌상단 우하단 두 칸
!타일 C7        한 칸
```

열 A~Q(17), 행 1~10. 오버레이 보드에 라벨을 크게 그려야 한다 — 시청자가 이걸 보고
타이핑하므로 라벨 가독성이 이 기능의 성패다.

## 원본에서 바꾸는 규칙과 그 이유

- **컬러타일 헛클릭 -10초 → 사용자별 쿨다운 5초.** 채팅은 수십 명이 동시에 쏜다.
  시간 차감을 그대로 두면 몇 초 만에 0이 되어 게임이 성립하지 않는다.
- **제한시간 2분 → 기본 5분(조절 가능).** 채팅 왕복 지연이 1~3초라 2분은 너무 짧다.
- **선물 보너스(옵션)** — 선물 시 시간 추가. tikke는 이미 선물 이벤트를 받고 있어 붙이기 쉽다.

## 아키텍처

| 위치 | 역할 |
|---|---|
| `packages/shared/src/minigame.ts` | 시드 RNG · 보드 생성 · 이동 검증 · 점수. **순수 함수만** |
| `electron/services/minigame-service.ts` | 방송 코옵 진행, 채팅 구독, 쿨다운, 오버레이 브로드캐스트 |
| `src/pages/MiniGame.tsx` | 설정 + 직접 플레이 + 룸 만들기/참가 |
| `public/overlays/minigame.html` | 보드 · 타이머 · 랭킹 송출 (worker 사본 필수) |
| `apps/worker/src/durable/GameRoom.ts` | 룸 대전 DO — 방코드, 시드, 타이머, 점수 |

### 로직을 shared에 두는 이유

같은 보드 생성·검증 코드를 세 곳(데스크탑 main, 렌더러, worker DO)이 써야 한다.
한 곳이라도 다르게 구현하면 "내 화면에선 지워졌는데 서버는 아니라고 함"이 된다.
그래서 `packages/shared`에 순수 함수로 두고 전부 그걸 import 한다.
DOM·Node API를 쓰면 worker에서 깨지므로 순수 함수만 허용한다.

`@tikke/shared`에서 **런타임 값**을 렌더러가 import 하는 건 원래 검은 화면 함정이었으나
(`electron.vite.config.ts`가 소스로 alias) 지금은 안전하다. 확인함.

### 룸 대전을 서버 권위로 두는 이유

클라이언트가 점수만 올려 보내면 조작이 자명하다. DO가 보드 상태를 들고 이동을 검증한다.
플레이어 수가 적어(방당 수 명) DO 부하는 무시할 수준이다.

`wrangler.toml`에 DO 바인딩을 추가하면 **migration tag를 v2로 올려야 한다**
(기존 v1은 `new_sqlite_classes = ["OverlayRoom"]`).

## 주의할 함정 (기존 사례에서)

- 오버레이 추가 시 체인을 끝까지 안 이으면 미리보기가 먹통이 된다 — `previewUrl`/`cloudUrl`
  누락이 가장 잦다. `SYNC_TYPES`(로컬·클라우드 양쪽), `getUrls()`, `EventOverlay` 카드까지.
- 오버레이 HTML은 `apps/worker/public/overlay/`에 **같은 파일을 복사**해야 한다.
  worker 배포는 `apps/worker/**` 경로 필터라 데스크탑만 고치면 라이브가 그대로다.
- `streamEnd`에 자동 stop을 걸지 말 것. TikTok "일시중지"도 streamEnd로 오는 탓에
  게임이 영구 정지한다 (시맨틀·초성퀴즈에서 제거한 이력).
- 오버레이 시각 버그는 typecheck로 안 잡힌다. `?test=1` + playwright 실측 필수.
