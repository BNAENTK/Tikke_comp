# context-notes — 사과게임 (Fruit Box)

## 2026-07-28

요청: gamesaien.com 「フルーツボックス」를 Tikke에 넣기. K님 선택 = **자체 구현** + **채팅 좌표 참여 & 선물 개입**.

### 원본을 임베드하지 않고 직접 만든 이유
원본을 스크랩해 확인한 결과 Adobe Animate(CreateJS) 퍼블리시 결과물이었다.

```
<script src=".../createjs-1.0.0.min.js"></script>
<script src=".../fruit_box_a_006_o.js"></script>
AdobeAn.getComposition("7475C6A158E3BF4B8C03C4B79FFD5BA3")
canvas 720×470
```

ゲーム菜園 소유물이고 오픈 라이선스 표기가 없다. 페이지에 구글 애드센스가 3곳 붙어 있어 iframe으로 넣으면 상용 데스크탑 앱이 남의 저작물과 광고를 대신 실어 나르는 꼴이 된다. 게다가 채팅/오버레이 연동이 불가능해 Tikke에 넣는 의미 자체가 없다. 그래서 **룰만** 가져와 새로 구현했다. 합 10을 묶는 퍼즐은 흔한 장르라 룰 자체는 문제되지 않는다.

### 게임 규칙
- 17열 × 10행 = 사과 170개, 값 1~9 무작위
- 좌표는 열 A~Q, 행 1~10. 채팅으로 두 좌표를 보내면 그 직사각형이 선택 범위
- 범위 안 **남은** 사과 합이 정확히 10이면 제거, 점수 = 제거한 개수
- 제한시간 기본 120초. 선물은 아래 "선물별 시간 규칙" 절 참고 (초기에는 모든 선물 +5초였다)

파싱 정규식은 `/([A-Qa-q])\s*(10|[1-9])\s*[-~,]?\s*([A-Qa-q])\s*(10|[1-9])/`. `A1 C3` / `a1c3` / `A1-C3` / `A1~C3` 를 모두 받는다. `10|[1-9]` 순서가 중요하다 — `[1-9]|10` 이면 "10"에서 1만 먹고 0이 남는다.

### 왜 매초 브로드캐스트하지 않는가
보드는 170칸이라 상태를 매초 보내면 오버레이/클라우드로 나가는 트래픽이 커진다. 그래서 상태 변화(제거·선물·시작/정지) 때만 보내고, **남은 시간은 오버레이가 스스로 카운트다운**한다.

`endsAt`(절대 epoch ms)과 `serverNow`를 같이 실어 보내고 오버레이가 `skew = serverNow - Date.now()`를 계산해 보정한다. 클라우드 오버레이는 다른 기기에서 열릴 수 있어 시계 차이를 그냥 무시하면 남은 시간이 어긋난다.

보드 자체도 배열이 아니라 **행마다 문자열 1줄**(`"56218917474359495"`, 0=제거)로 압축해 보낸다.

### 선물 처리 — 다이아 규모에 비례시키지 않은 이유 (초기 구현, 이후 규칙 방식으로 교체됨)
개입 수단이 "시간 추가" 하나뿐이라, 다이아에 비례시키면 큰 선물 하나로 판이 무한정 늘어난다. 여러 명이 여러 번 참여하는 쪽이 방송에 낫다고 보고 **선물 1회당 고정 초**로 했다(`fruitBoxGiftAddSec`, 기본 5).

연타 선물은 `isStreakEnd === false`인 중간 이벤트를 건너뛰고 종료 시점만 집계한다.

기여자는 `giftHelps`에 닉네임별 누적 초로 쌓고 상위 20명만 유지한다. 장시간 방송에서 무한히 늘지 않게 하기 위해서다.

기존 게임 중 **선물 이벤트를 구독하는 건 이 게임이 처음**이다(초성퀴즈·시맨틀·그림퀴즈는 채팅만). 선물 구독 선례는 top-donor-service 뿐이었다.

### streamEnd 자동 정지 없음
초성퀴즈·시맨틀과 같은 판단이다. TikTok "일시중지"도 streamEnd로 오기 때문에 자동으로 멈추면 일시중지 한 번에 게임이 죽는다.

### 테스트 환경에서 헷갈렸던 것 두 가지 (버그 아님)
1. **오버레이 HTTP가 전부 404** — `electron out/main/index.js`로 언패키지 실행하면 `app.getAppPath()`가 `out/`을 가리켜 `public/overlays`를 못 찾는다. `chat`·`choseong-quiz`도 똑같이 404다. `pnpm dev`나 설치본에서는 정상.
2. **최근 제거 배지가 스크린샷에 안 보임** — `show:false` 히든 창에서는 나중에 삽입된 요소의 CSS 애니메이션이 0% 프레임에 멈춘다(`opacity:0`, `scale(.7)`). 창을 띄우면 `opacity:1`, `transform:none`. 기존 초성퀴즈 `#result`도 같은 `popIn` 패턴이라 실제 브라우저 소스에서는 정상 동작한다.

## 2026-07-28 (추가) — 방송인 마우스 드래그 플레이

채팅 참여형으로 확정했었으나 K님 요청으로 호스트 직접 플레이를 추가했다.

호스트 패널의 보드 미리보기를 그대로 인터랙티브하게 만들었다. 별도 IPC를 새로 파지 않고 드래그가 끝나면 좌표를 `"E1 F1"` 문자열로 만들어 기존 `hostPick`에 넘긴다. 화면에서 계산한 합은 어디까지나 표시용이고 **실제 판정은 놓는 순간 서비스가 다시 한다** — 상태 폴링이 1초라 화면 보드가 살짝 오래됐을 수 있기 때문이다.

- 드래그 중 선택 영역에 아웃라인을 그린다. 합이 10이면 초록, 넘으면 빨강, 그 외 시안
- 마우스를 보드 밖에서 떼도 끝나야 하므로 `mouseup`은 `window`에서 받는다
- 성공 시 폴링을 기다리지 않고 `getState()`를 한 번 더 호출한다. 안 그러면 제거된 사과가 최대 1초간 남아 보인다
- 셀 크기를 20px → 24px로 키웠다 (드래그 대상이 되었으므로)

### 드래그 검증에서 헤맸던 것 (제품 버그 아님)
CDP로 합성 마우스 이벤트를 보내 테스트했더니 드래그가 `D1 → H7`, `D1 → L8` 처럼 엉뚱한 칸에서 끝났다. 레이아웃이 밀리는지 의심해 `getBoundingClientRect`와 스크롤 위치를 재봤지만 전부 고정이었고, `elementFromPoint`도 올바른 셀을 가리켰다.

원인은 **실제 OS 커서**였다. 앱 창이 보이는 상태에서 진짜 커서가 보드 위에 놓여 있으면, 합성 이벤트와 무관하게 진짜 `mouseenter`가 발생해 드래그 끝점을 덮어썼다. PowerShell로 커서를 화면 구석(5,5)으로 옮기고 다시 돌리니 `D1 E1`로 정확히 잡혔고, 합 10 구간(`E1 F1`)을 드래그하니 사과 2개가 제거되고 리더보드에 "호스트 2개"가 찍혔다.

교훈: **Electron 창이 보이는 상태에서 CDP 합성 마우스 이벤트로 드래그를 테스트하려면 실제 커서를 먼저 치워야 한다.** 안 그러면 없는 버그를 쫓게 된다.

또 하나, 진단 중 "합 10"이 항상 표시되는 것처럼 보였는데 이건 정규식 `/합 \d+/`가 화면의 정적 안내문구 "…합 10일 때 제거됩니다"에 걸린 오측정이었다.

## 2026-07-28 (추가) — 선물별 시간 규칙

기존에는 **모든** 선물이 고정 초(`fruitBoxGiftAddSec`, 기본 5초)를 더했다. K님 요청으로 **호스트가 지정한 선물만** 영향을 주고, 초를 음수로 두면 시간이 깎이도록 바꿨다.

### 설정 형태
`fruitBoxGiftAddSec`(number)를 제거하고 `fruitBoxGiftRules`(JSON 문자열)로 교체했다. 설정에 JSON을 문자열로 넣는 건 이 저장소 관례를 따른 것이다.

```json
[{ "giftId": 5655, "giftName": "장미", "sec": 20 },
 { "giftId": 36967, "giftName": "아톰팀 폭탄", "sec": -30 }]
```

- 선물 1개당 규칙 1개. 같은 선물을 다시 추가하면 기존 규칙을 덮어쓴다
- 초는 ±300으로 클램프하고 0은 무시한다
- 규칙에 없는 `giftId`는 **아무 일도 일어나지 않는다**(기존처럼 기본 추가 없음)
- JSON이 손상되면 규칙 없음으로 취급한다

### 시간이 0 이하로 깎이면
`endsAt`을 `Math.max(now, endsAt + sec*1000)`으로 막고, 결과가 현재 시각이면 그 자리에서 `finish()`를 부른다. 음수 타임아웃으로 타이머를 다시 걸면 안 되기 때문이다. 이때도 기여 기록은 남긴다.

### 표시
`giftHelps`에 `giftName`을 같이 담고 **영향이 큰 순(절대값)**으로 정렬한다. 도움과 방해가 섞이므로 크게 도운 사람과 크게 방해한 사람이 둘 다 보이는 쪽이 맞다고 봤다. 호스트 패널과 오버레이 모두 양수는 초록/노랑, 음수는 빨강으로 부호와 함께 표시한다. 패널 라벨은 "시간 후원" → "선물 효과"로 바꿨다.

선물 선택 UI는 기존 공용 `components/GiftPicker`(검색 드롭다운)를 그대로 썼다. EventOverlay·Gta5·TimerSettings가 이미 쓰는 컴포넌트다.

### 검증
실행 중인 앱에 CDP로 붙어 확인했다.

| 케이스 | 결과 |
|---|---|
| 등록 선물 장미(+20) | 120 → 140초 (정확히 +20) |
| 미등록 선물(9999) | 변화 없음 (경과분 -1초만) |
| 등록 선물(-30) | 139 → 109초 (정확히 -30) |
| 규칙 목록 비움 | 등록했던 장미도 영향 없음 |
| -300초로 0 이하 | `running:false`, 판 종료 |

`giftHelps`는 `[{심술쟁이, -30, …}, {도움이, +20, 장미}]`로 절대값 순 정렬 확인.

검증에 쓴 음수 규칙의 giftId 5657은 **카탈로그에 없는 임의 id**였다. 로직 검증에는 문제가 없었지만(등록된 id면 반영, 아니면 무시) 실재하는 선물이 아니므로 예시로 삼지 말 것. 실제 폭탄류는 36967 아톰팀 폭탄, 50703 멋짐 폭발이며 둘 다 1다이아다.

### 테스트에서 걸린 것 (제품 버그 아님)
CDP 타깃을 `type === "page"`로만 고르면 **room-observer가 만드는 히든 BrowserWindow**가 먼저 잡혀 `window.tikke`가 undefined였다. 렌더러 URL(`out/renderer/index.html`)로 걸러야 한다. 다음에 이 앱을 CDP로 붙일 때 같은 함정에 빠지지 말 것.

## 2026-07-28 (추가) — 초 입력창에서 하이픈 입력

`type="number"` 입력창은 `-`만 친 중간 상태에서 `e.target.value`가 **빈 문자열**을 돌려준다. 그래서 `Number("")`가 0이 되어 음수를 칠 수가 없었다 — `-`를 누르는 순간 0으로 튀고, 이어서 `30`을 치면 `-30`이 아니라 `30`이 된다.

`type="text" inputMode="numeric"`으로 바꾸고 값을 **문자열로 들고 있다가** 완성됐을 때만 숫자로 커밋한다.

```ts
const SEC_TYPING = /^-?\d*$/;              // 입력 중 허용: "", "-", "-3"
function parseSec(text: string): number | null {
  if (!/^-?\d+$/.test(text)) return null;  // "" 와 "-" 는 아직 값이 아님
  const n = Math.round(Number(text));
  if (!Number.isFinite(n) || n === 0) return null;
  return Math.max(-300, Math.min(300, n));
}
```

- 추가 폼: `newSecText`(문자열) 보관, `parseSec`가 null이면 "추가" 버튼 비활성
- 목록 행: `secText`(giftId → 입력 중 문자열) 오버레이를 두고, `parseSec`가 값을 낼 때만 저장한다. 그래서 `-`만 친 순간에는 기존 값이 0으로 덮이지 않는다. blur 시 오버레이를 지워 저장값 표시로 되돌린다

검증(실제 키 입력): 추가 폼 `-` → `-3` → `-30`. 목록 행은 `-`(저장 안 됨, 기존 20 유지) → `-4`(저장) → `-45`(저장), blur 후 `-45초` 표시. 새로고침 후에도 `[장미 20, 아톰팀 폭탄 -15]`가 음수 포함해 그대로 로드됨.

### 테스트에서 걸린 것 (제품 버그 아님)
1. CDP `Input.dispatchKeyEvent`로 `keyDown`에 `text`를 실으면서 `char`도 보내면 **글자가 두 번 입력된다**(`3` → `33`). `char`만 보내야 한다.
2. 사이드바 메뉴는 `<button><span>사과게임</span></button>` 구조다. `el.closest('div[style]')`로 올라가면 버튼을 건너뛴 바깥 div를 눌러 **페이지 이동이 안 된다**. `el.closest('button')`을 써야 한다. 이것 때문에 "규칙이 로드되지 않는다"고 한동안 오해했다.

## 2026-07-28 (추가) — 합 10 성공 효과음

에셋 파일 없이 **WebAudio로 합성**했다. roulette / roulette-circular / slot-machine 오버레이가 쓰는 방식과 같다. 파일을 쓰면 desktop과 worker 양쪽에 배치하고 경로까지 맞춰야 하는데, 짧은 효과음은 합성이 훨씬 싸다.

소리는 두 겹이다.
- **pop** — 삼각파를 520→180Hz로 빠르게 떨어뜨리는 0.12초 블립. 사과가 톡 터지는 느낌
- **chime** — C 펜타토닉(523/587/659/784/880/1046Hz) 상승 아르페지오. 55ms 간격

**지운 사과 개수에 따라 커진다.** `n = clamp(count,1,6)`으로 pop 시작 주파수를 `520+n*40`, 음 개수를 `2+floor(n/2)`(최대 6)로 잡았다. 2개 지우면 3음, 4개 지우면 4음. 크게 지울수록 보상감이 커진다.

`?mute=1`로 끌 수 있다(roulette과 동일한 파라미터명). 이때는 AudioContext 자체를 만들지 않는다.

### 새로고침 때 울리지 않게
`lastClear`는 상태 스냅샷에 들어 있어서, 오버레이를 새로고침하면 이미 지나간 제거 기록이 다시 들어온다. `firstState` 플래그를 두고 **처음 받은 상태에서는 효과음과 pop 연출을 건너뛴다.** 워커가 재연결한 오버레이에 스냅샷을 다시 쏴주는 구조라(`OverlayRoom`) 이 가드가 없으면 새로고침할 때마다 소리가 난다.

### 검증
`Input.dispatchKeyEvent` 같은 실제 재생 확인이 어려워, preload로 `window.AudioContext`를 가로채 호출을 세는 방식으로 확인했다.

- `?test=1` (제거 2회: 4개 → 2개) → `ctxCreated:1`, 오실레이터 `start` 9회
  - 4개 제거 = pop 1 + chime 4 = 5, 2개 제거 = pop 1 + chime 3 = 4. 설계대로 개수에 비례
  - 시작 시각도 `[0, .05, .105, .16, .215]`, `[0, .05, .105, .16]`으로 아르페지오 간격 55ms 일치
- `?test=1&mute=1` → `ctxCreated:0`, 오실레이터 0회

### 남은 것
호스트 패널(드래그 플레이)에서는 소리가 나지 않는다. 소리는 오버레이(브라우저 소스)에서만 난다 — 방송에 나가는 건 그쪽이기 때문이다. 방송인이 직접 듣고 싶으면 TTLS 브라우저 소스의 오디오 모니터링을 켜면 된다.
