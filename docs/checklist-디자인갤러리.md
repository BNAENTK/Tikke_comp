# 디자인 갤러리 — 체크리스트

최고 후원자 오버레이 디자인을 사용자끼리 공유. 갤러리에서 클릭 한 번으로 적용.
K 결정: **누구나 업로드**, **사이드바 별도 메뉴**.

## 이미 있는 것 (재사용)
- `overlayShareCode.ts` — 허용 목록 기반 인코딩. 비밀값이 구조적으로 못 들어간다
- TopDonor iframe 미리보기 — 실제 오버레이 HTML + postMessage. **썸네일 업로드 불필요**
- Supabase 인증 — 업로더 신원 확보 가능

## 보안 (공개 업로드라 필수)
- [x] 1. 문자열 값 형태 검증 — 지금은 길이(2000)만 본다.
      색상 값이 CSS 커스텀 속성으로 들어가 `var()` 치환 시 선언 주입이 가능하다
      (`"red; background-image: url(외부주소)"` → 남의 화면이 외부 요청을 보냄).
      색상 키는 색상 패턴만, 폰트 키는 알려진 목록만 허용.
- [x] HTML 주입 — `renderText`가 `textContent`만 쓴다. `innerHTML`은 비우기 전용. 안전 확인
- [x] 2. 업로드에 로그인 요구 + 사용자당 개수·빈도 제한
- [x] 3. 신고 + 자동 숨김 + K 검토(확인 완료/직접 숨기기). 확인 완료 시 자동숨김 면제

## 서버
- [x] 4. `overlay_presets` 테이블 + RLS (본인 것만 수정/삭제, 읽기는 공개)
- [x] ~~워커 라우트~~ 불필요 — RLS가 전부 강제하므로 앱이 Supabase와 직접 통신. 표면 축소 — 목록(정렬·페이징), 업로드, 신고
- [x] 6. 사용 수 집계 (preset_use RPC) (인기순 정렬용)

## 앱
- [x] 7. `DesignGallery.tsx` — 카드 격자, 각 카드에 축소 iframe 실시간 렌더
      **화면에 보이는 카드만 iframe 생성**(IntersectionObserver). 안 그러면 iframe 수십 개가 뜬다
- [x] 8. 클릭 한 번 적용 — 기존 decode 경로 재사용
- [x] 9. 내 디자인 올리기 (이름·설명 입력)
- [x] 10. 사이드바 메뉴 + 라우팅
- [x] typecheck + 렌더러 빌드 통과
- [x] 실제 화면 확인 — 하네스로 렌더. 카드 2장 실물 미리보기 정상, 적용 경로 정상(키 40개 전달)

## 하지 않는 것
- 썸네일 이미지 업로드 — 실시간 렌더가 있어 불필요하고, 이미지 업로드는 저장 비용·검열 부담이 크다
- 프리셋(AppSettings 전체) 공유 — 비밀값이 섞인다. 반드시 공유 코드 경로만 쓴다
