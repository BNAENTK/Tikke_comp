# 선물 이펙트 공용 배포 — 결정 사항

## 문제
K가 "내 로컬 영상이 다른 사용자에게 배포가 안 된다"고 했다. 확인해 보니 두 가지였다.

1. **메뉴가 개발 모드에서만 열린다.**
   `case "giftfx": return import.meta.env.DEV ? <GiftFx /> : <Dashboard />;`
   배포된 앱에서는 "선물 이펙트"를 눌러도 대시보드가 뜬다.
   **K 지시로 이 잠금은 유지한다** — 한 번 풀었다가 되돌렸다. 카탈로그만 미리 배포해 두고
   메뉴를 여는 시점은 K가 정한다.

2. **목록이 각자 자기 방송에서만 쌓인다.**
   `userData/gift-asset-cache.json` 에 방송 중 캡처된 선물이 저장된다. K는 99개가 쌓였지만
   새 사용자는 0개다. 큰 선물은 자주 안 오니 언제 채워질지 기약이 없다.

## 영상 파일은 옮기지 않는다
`videoUrl` 은 TikTok CDN 주소다(p16/sf16-webcast.tiktokcdn.com). 파일을 배포할 필요 없이
**목록(JSON)만** 내려 주면 된다. 5,000코인 이상 35개 기준 23KB.

## 서버에서 받기 (K 선택)
앱 동봉 대신 서버에서 받는다 — K가 새 선물을 모았을 때 **앱을 새로 배포하지 않고** 반영된다.
`apps/worker/public/gift-effects.json` 에 두고 `https://api.tikke.kr/gift-effects.json` 로 서빙.
wrangler 의 `run_worker_first` 가 `/overlay/*` 만 지정하므로 나머지는 정적 자산이 우선이라
별도 라우트가 필요 없다.

## 5,000코인 이상만 (K 지시)
K 캐시 96개 중 35개가 해당한다(유니버스 44,999 ~ 다이아몬드건 5,000).
상수 `GIFT_FX_MIN_DIAMOND = 5000` 으로 목록 조회에서 거른다. 카탈로그 생성 시에도 같은
기준으로 잘라 서버에 올린다(두 겹).

## 합치는 규칙
서버 카탈로그를 먼저 깔고 **내가 캡처한 것으로 덮는다**. 같은 giftId 면 캡처분이 이긴다 —
내 방송에서 실제로 받은 주소가 더 최신이다. 서버 응답도 그대로 믿지 않고 재생에 필요한
최소 조건(https videoUrl, 이름)만 통과시킨다.

## 공개 안전성 확인
카탈로그에 담긴 필드는 giftId·name·diamond·picUrl·zipUrl·videoUrl 뿐이다.
세션·토큰·방ID·사용자ID 같은 값은 없고, 참조 호스트도 TikTok CDN 두 곳뿐이다(실측 확인).

## 남은 것
- 갱신 방법: 지금은 K 캐시에서 뽑아 커밋한다. 자주 갱신할 거면 뽑는 스크립트를 두는 편이 낫다.
- 사용자가 6시간마다 다시 받는다(`REFRESH_MS`). 실패하면 로컬 캡처분만 쓴다.
