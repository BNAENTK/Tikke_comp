# 유튜브 신청곡 — 결정과 이유

## 무엇
시청자가 채팅으로 `!신청 <검색어>` 를 치면 tikke 가 유튜브에서 찾아 큐에 넣고,
오버레이(TTLS 브라우저 소스)에서 순서대로 재생한다. 곡 정보도 화면에 띄운다.

K 선택: **앱 안에서 재생**(큐만 관리하는 방식이 아니라).

## 검색을 yt-dlp 로 하는 이유
YouTube Data API 는 키가 필요하고 하루 할당량이 있다. 신청이 몰리면 바로 막힌다.
tikke 는 이미 **yt-dlp 를 설치해 두고 있다**(유튜브 음원 추출 기능). `ytsearch1:<검색어>` 로
검색 결과를 JSON 으로 받을 수 있어 키도 할당량도 필요 없다.

같은 이유로 재생 자체는 **유튜브 IFrame 플레이어**로 한다 — 음원을 내려받아 재생하면
저작권 처리가 달라지고 용량도 문제가 된다. iframe 은 유튜브가 정한 방식으로 재생하는 것이다.

## 신청 입력 — 검색어와 링크 둘 다
`!신청 아이유 밤편지` 처럼 **가수+제목**으로 검색하거나, `!신청 https://youtu.be/...` 처럼
**유튜브 링크**를 그대로 붙여도 된다. 제목만으로는 원하는 영상이 안 걸리는 경우가 있어서다.

받는 형태: `youtube.com/watch?v=`, `youtu.be/`, `m.`·`music.` 하위 도메인,
`/shorts/`·`/embed/`·`/live/`, 그리고 11자 영상 ID 단독.

두 가지를 지킨다.
- **허용 호스트를 고정한다.** 임의 문자열이 yt-dlp 인자로 흘러가면 안 된다 —
  `-` 로 시작하는 값은 플래그로 먹힌다(음원 추출 쪽과 같은 방침).
- **`--no-playlist`** 를 붙인다. 링크에 `&list=` 가 있으면 재생목록 전체가 딸려 온다.

## TIK SCAN 의 결함을 피한다
저쪽 구현을 뜯어보고 기록해 둔 문제(`context-notes-tikscan-reverse.md` §4):

1. **곡이 끝날 때만 다음 곡을 트리거한다.** 플레이어가 멈춰 있으면 신청곡이 쌓이기만 하고
   자동으로 시작되지 않는다 — 방송인이 수동으로 한 곡 틀어줘야 체인이 돈다.
   → 우리는 **큐가 0→1 이 되는 순간에도 재생을 건다.** 재생 중이 아니면 즉시 시작한다.
2. **쿨다운을 검색 전에 기록한다.** 검색이 실패해도 30초를 날리고, 차단된 사용자에게
   아무 피드백도 안 준다.
   → 쿨다운은 **큐에 실제로 들어간 뒤** 기록한다. 실패하면 다시 시도할 수 있다.
3. **포트 6969 고정, 폴백 없음.** 포트가 점유되면 음악 기능 전체가 죽는다.
   → 우리는 별도 포트를 열지 않는다. 기존 오버레이 서버(18181/18182)를 그대로 쓴다.

## 자동 재생
브라우저는 사용자 조작 없는 소리 재생을 막는다. TTLS 브라우저 소스에서는 대개 허용되지만
보장은 없다. 그래서 오버레이는 **재생이 시작되지 않으면 "재생하려면 클릭" 안내를 띄운다** —
조용히 멈춰 있는 것보다 낫다. 상태를 앱으로도 보고해 큐 화면에서 알 수 있게 한다.

## 누가 신청할 수 있나 (두 겹, 둘 다 통과해야 함)

**1) 등급 제한** — 기본 `모두`. 팔로워 / 팀 멤버 / 구독자 / 최고 후원자 / 모더레이터 중 선택.
명령어 기능의 `checkPermission` 을 그대로 쓴다 — 권한 판정이 두 벌이면 언젠가 갈린다.
모더레이터는 모든 등급을 통과한다(기존 규칙 유지).

**2) 선물 티켓제** (기본 꺼짐) — 켜면 **기준 코인 이상 선물한 사람만** 신청할 수 있다.
- 지급 조건을 세 가지로 고른다 — `코인 기준` / `지정한 선물만` / `둘 중 하나`.
  코인 기준만 두면 "이 선물을 보내야 신청 가능" 같은 운영을 못 한다(K 요청).
  `지정한 선물만` 인데 목록이 비어 있으면 코인 기준으로 되돌린다 — 설정을 하다 만 상태에서
  아무도 티켓을 못 받고 기능이 조용히 죽는 것보다 낫다.
- 조건을 만족하는 선물마다 신청권 1장.
- **신청이 성공했을 때만 차감한다.** 검색 실패로 못 담았는데 티켓을 잃으면 항의가 온다.
- 콤보는 **종료분만** 센다(`repeatEnd === false` 는 진행 중 중복이라 티켓이 부풀어 오른다).
- 방송이 끝나면 비운다 — 다음 방송으로 넘기면 그날 선물한 사람과 형평이 어긋난다.

둘은 AND 로 걸린다. 예: 등급 `팀 멤버` + 티켓제 켜짐 → 팀 멤버이면서 선물도 한 사람만 신청 가능.

## 방송인이 곡을 넘긴다
부적절한 곡이 걸릴 수 있으므로 언제든 넘길 수 있어야 한다.
- 신청곡 화면의 `다음 곡` 버튼
- **덱 액션** `신청곡 다음 곡` / `신청곡 대기열 비우기` — 방송 중엔 앱이 뒤에 있으므로
  항상 위에 뜨는 덱 창이나 스트림덱에서 눌러야 실효가 있다

**넘긴 곡은 그 방송 동안 다시 못 올라온다.** 스킵만으로는 구멍이 남는다 —
넘겨도 시청자가 같은 곡을 또 신청하면 그대로 다시 나온다. 대기열에 같은 곡이 이미
들어 있으면 함께 걷어낸다. 차단은 방송 단위이고, 화면에서 수동 해제할 수 있다.

## 남용 방지
- 사용자당 쿨다운(기본 60초)
- 곡 길이 상한(기본 10분) — 한 명이 긴 영상으로 큐를 점유하는 것 방지
- 큐 길이 상한(기본 20)
- 사용자당 대기 곡 수 상한(기본 1)
- 권한 설정(전체 / 팔로워 / 구독자 / 모더레이터)

## 안 하는 것
- 음원 다운로드 후 로컬 재생: 저작권·용량 문제. iframe 재생만.
- Spotify 연동: 별건. 지금은 유튜브만.
